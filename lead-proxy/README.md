# Прокси для заявок

Прячет токен Telegram-бота. Браузер отправляет заявку на URL прокси, прокси сам
обращается к Telegram — токен хранится на его стороне и в исходники страницы не
попадает.

Два варианта, код независимый, разворачивать нужно **только один**:

| Файл | Где живёт | Годится для России |
|---|---|---|
| [`yandex-function.js`](yandex-function.js) | Yandex Cloud Functions | **да — этот и используем** |
| [`cloudflare-worker.js`](cloudflare-worker.js) | Cloudflare Workers | нет: `*.workers.dev` в России часто заблокирован |

Cloudflare оставлен на случай, если сайт когда-нибудь будет рассчитан на
зарубежную аудиторию. Для российских посетителей он не подходит: домен
`workers.dev` массово используют для обхода блокировок, из-за чего он попал под
ограничения, и часть людей до прокси просто не дозвонится. Заявка при этом
потеряется молча — человек увидит подтверждение на сайте, а сообщение не придёт.

# Yandex Cloud Functions

Бесплатного тарифа хватает с огромным запасом: 1 000 000 вызовов функций в
месяц. Лендинг с заявками не выйдет за него никогда — счёт останется нулевым.

## Регистрация

Пропустить, если аккаунт Yandex Cloud уже есть.

1. Открыть [console.yandex.cloud](https://console.yandex.cloud) и войти под
   Yandex ID (той же учётной записью, что почта на Яндексе). Если её нет —
   завести, потребуется подтверждение по телефону.
2. При первом входе консоль попросит создать **платёжный аккаунт**: тип
   плательщика «Физическое лицо», страна, и привязать карту. Карта нужна для
   верификации даже при нулевом расходе — обычно списывается и возвращается
   небольшая сумма. Новым пользователям дают пробный грант.
3. Вместе с аккаунтом автоматически создаётся облако и каталог `default` —
   отдельно ничего создавать не нужно.

Без платёжного аккаунта сервисы не включатся, поэтому шаг 2 обязателен. Дальше
всё бесплатно в рамках лимитов выше.

## Разворачивание через консоль

Без установки чего-либо, весь путь в браузере.

1. Открыть [console.yandex.cloud](https://console.yandex.cloud), создать
   каталог (или взять `default`).
2. **Cloud Functions** → **Создать функцию** → имя `lumier-leads` → создать.
3. Открылся редактор версии. Выставить:
   - **Среда выполнения** — `nodejs22` (подойдёт любая `nodejs18` и новее);
   - **Способ** — «Редактор кода»;
   - **Точка входа** — `index.handler`;
   - файл назвать `index.js` и вставить в него содержимое
     [`yandex-function.js`](yandex-function.js).
4. Ниже, в **Параметрах**:
   - **Таймаут** — `10` секунд;
   - **Память** — `128` МБ;
   - **Переменные окружения** — добавить две:
     - `BOT_TOKEN` — токен от @BotFather,
     - `CHAT_ID` — `-5163834689` (**минус обязателен**, см. ниже).
5. **Создать версию**.
6. Вкладка **Обзор** → включить **Публичная функция**. Без этого браузер
   получит `403`: вызов будет требовать IAM-токен.
7. Скопировать **ссылку для вызова** — вид
   `https://functions.yandexcloud.net/d4e...`. Это адрес прокси.

Переменные окружения видны всем, у кого есть доступ к каталогу в консоли, но
наружу не отдаются. Если нужно строже — вынести `BOT_TOKEN` в
[Yandex Lockbox](https://yandex.cloud/ru/docs/functions/concepts/secrets) и
подключить секрет к функции; код при этом не меняется, значение так же
приезжает в `process.env`.

## Подключение к сайту

В `LEAD_CONFIG` (начало `js/main.js`):

```js
telegram: { token: "", chatId: "" },              // остаётся пустым
webhook:  "https://functions.yandexcloud.net/d4e..."
```

Оба канала одновременно не нужны: `telegram` шлёт из браузера напрямую и
раскрывает токен, `webhook` — через прокси. Заполнен должен быть только `webhook`.

## Проверка

```bash
curl -i -X POST https://functions.yandexcloud.net/d4e... \
  -H "Content-Type: application/json" \
  -H "Origin: https://veshaem-girlyandi.ru" \
  -d '{"source":"проверка curl","name":"Тест","phone":"+7 977 134-48-44"}'
```

Ожидаем `200` и `{"ok":true}`, в чате — сообщение. Полезные проверки отказов:

- без заголовка `Origin` → `403 origin_not_allowed`;
- без поля `phone` → `400 phone_required`;
- метод `GET` → `405 method_not_allowed`.

Логи и ответы Telegram: в консоли функции вкладка **Логи**.

# Cloudflare Workers (вариант для не-России)

```bash
cd lead-proxy
npx wrangler login          # откроет браузер, попросит войти в Cloudflare
npx wrangler secret put BOT_TOKEN   # вставить токен от @BotFather
npx wrangler secret put CHAT_ID     # -5163834689
npx wrangler deploy
```

`wrangler secret put` спрашивает значение в консоли и не пишет его в файлы —
поэтому секреты задаются именно так, а не через `wrangler.toml`.

Команда напечатает URL вида `https://lumier-leads.<аккаунт>.workers.dev` — его
и вписать в `webhook`. Живые логи: `npx wrangler tail`.

Ограничение частоты здесь работает на KV и включается отдельно:

```bash
npx wrangler kv namespace create RL
```

Напечатанный `id` подставить в блок `[[kv_namespaces]]` в `wrangler.toml`,
раскомментировать его и снова `npx wrangler deploy`.

# Общее для обоих вариантов

## Что прокси проверяет

| Проверка | Зачем |
|---|---|
| `Origin` из списка `ALLOWED_ORIGINS` | чужой сайт не будет слать заявки через наш прокси |
| тело до 4 КБ, поля до 300 символов | чат не залить простынёй текста |
| обязательный `phone` | заявка без телефона бесполезна |
| сообщение собирается на стороне прокси | текст в чате не диктуется целиком снаружи |
| неизвестные поля отбрасываются | в сообщение не дописать произвольные строки |
| лимит частоты | 5 заявок с одного IP за 10 минут |

Лимит частоты в обоих вариантах приблизительный: у Яндекса счётчик живёт в
памяти экземпляра функции, у Cloudflare — в KV с неполной согласованностью.
Он против болтливого скрипта, а не против распределённой атаки.

Список `ALLOWED_ORIGINS` включает кириллический домен в punycode
(`xn----7sbfgfcb0a1agp8a5g6b3c.xn--p1ai`) — браузер отдаёт `Origin` именно
в таком виде. При смене домена список надо править в том файле, который
развёрнут.

## Если понадобится другой чат

Добавить бота в новую группу и поменять `CHAT_ID`. **У групп id отрицательный** —
без минуса Telegram отвечает `400 Bad Request`. Узнать id:
`https://api.telegram.org/bot<ТОКЕН>/getUpdates` после любого сообщения в группе.

## Чего это не решает

URL прокси всё равно виден в исходниках страницы, так что слать в чат
бессмысленные заявки через него по-прежнему можно. Разница в том, что у
постороннего нет самого токена: он не может ни выгнать бота из группы
(`leaveChat`), ни читать обновления (`getUpdates`), ни использовать бота где-то
ещё. А поток мусора чинится лимитом частоты или сменой URL прокси — без
перевыпуска токена и без правки бота.
