# Lumiér — лендинг «украшение домов гирляндами под ключ»

Второй лендинг для клиента (вешаем-гирлянды.рф) на чистом **HTML + CSS + JS**, без сборки и зависимостей (кроме Google Fonts). Бренд **Lumiér**, стиль — тёмно-изумрудный «новогодний люкс».

## Структура
```
index.html          ← вся страница (разметка + SEO/JSON-LD/OG)
css/styles.css       ← дизайн-система и адаптив
js/main.js           ← квиз-калькулятор, до/после, модалки, карусель, маска телефона
assets/              ← сюда положить картинки из IMAGES.md (создайте папку)
assets/projects/     ← реальные фото объектов из ТЗ клиента (5 проектов, 23 кадра)
IMAGES.md            ← промпты изображений + куда что вставить
ЦА-и-аудит.md        ← портреты ЦА, прогон, дизайн-ревью, антиИИ-проверка
```

## Как открыть
Просто открыть `index.html` в браузере. Для корректной работы шрифтов/иконок лучше через локальный сервер:
```bash
# из папки проекта
python -m http.server 8080
# затем http://localhost:8080
```

## Настройка заявок

Сайт статический (GitHub Pages), бэкенда нет. Заявка уходит **параллельно во все каналы**, у которых заполнены поля в `LEAD_CONFIG` (начало `js/main.js`); незаполненные пропускаются. Форма работает в любом случае — пользователь всегда видит подтверждение.

| Канал | Что заполнить | Куда идёт |
|---|---|---|
| `email.endpoints` | адреса FormSubmit | письмо на каждый адрес независимо |
| `telegram` | `chatId` в коде, `token` — секретом при сборке | сообщение в группу заявок |
| `webhook` | URL прокси из [`lead-proxy/`](lead-proxy/), необязательно | то же, но токен вообще не попадает в браузер |

### Почта

Endpoint'ы уже вписаны. Каждый адрес нужно один раз подтвердить: FormSubmit присылает на него письмо со ссылкой «Activate Form». `gazovik7@gmail.com` подтверждён, **`girlandahous@yandex.ru` — нет**, письма на боевой ящик клиента пока не доставляются. Неподтверждённый адрес не мешает остальным.

### Telegram

Бот `@veshaemgirlyandirubot` и группа «New site (заявки) | Вешаем-гирлянды.рф» (`chat_id` `-5163834689`) готовы, доставка проверена.

> 🚫 **Этот путь сейчас нерабочий.** GitHub Actions отключены на уровне аккаунта («GitHub Actions is currently disabled for your account»), включить их может только поддержка GitHub — настройка репозитория такое не перебивает. Поэтому Pages публикуются с ветки, воркфлоу не запускается, и токен подставить негде: канал Telegram выключен, заявки идут только на почту. Рабочий способ включить Telegram — прокси, см. ниже. Если поддержка вернёт Actions, всё описанное здесь заработает без изменений в коде.

Идея: токен **в репозитории не хранится**, а подставляется при публикации. Что для этого нужно:

1. **Settings → Secrets and variables → Actions → New repository secret**, имя `TG_BOT_TOKEN`, значение — токен от @BotFather. *(уже сделано)*
2. **Settings → Pages → Source** переключить с «Deploy from a branch» на **«GitHub Actions»**. *(делать только после того, как Actions разблокируют, иначе сайт перестанет публиковаться)*

Тогда каждый push в `master` запускает [.github/workflows/pages.yml](.github/workflows/pages.yml): workflow пишет токен в `js/lead-secrets.js` и публикует сайт. Пока секрет не задан или Actions недоступны, канал Telegram просто пропускается — заявки идут на почту, формы работают как обычно. Так же выглядит и локальный запуск.

> ⚠️ **Что это решает и что нет.** Токен не попадает в репозиторий и в историю коммитов — его не найдут сканеры, которые непрерывно вычёсывают публичный GitHub на такие токены, и перевыпуск токена наконец имеет смысл. Но заявку отправляет браузер, поэтому **на живой странице токен по-прежнему виден через «просмотр кода»**. С ним посторонний может спамить в группу и выгнать бота из неё (`leaveChat`) — то есть тихо оборвать канал. Полностью убирает токен из браузера только прокси, см. ниже.

> **Если понадобится другой чат.** Добавить бота в новую группу и поменять `chatId` в `js/main.js`. **У групп id отрицательный** — без минуса Telegram отвечает `400 Bad Request`. Узнать id: `https://api.telegram.org/bot<ТОКЕН>/getUpdates` после любого сообщения в группе.

### Прокси — рабочий способ включить Telegram

Пока Actions заблокированы, это **единственный** путь получать заявки в Telegram, не выкладывая токен в публичный репозиторий.

В [`lead-proxy/`](lead-proxy/) лежит готовая функция для Yandex Cloud Functions: она держит токен у себя и сама пишет в группу, в браузер токен не попадает совсем — то есть защита даже лучше, чем у варианта со сборкой. Нужен аккаунт Yandex Cloud с платёжным аккаунтом; вызовы бесплатны (1 млн в месяц). От GitHub прокси не зависит вообще.

Развернуть, вписать выданный URL в `webhook` — инструкция в [lead-proxy/README.md](lead-proxy/README.md). Поля `telegram` остаются пустыми: оба канала одновременно включать не нужно, заявка придёт дважды.

> 🇷🇺 **Почему Яндекс, а не Cloudflare.** Адреса `*.workers.dev` в России часто заблокированы — их массово используют для обхода блокировок, и часть посетителей до такого прокси не дозвонится. Заявка при этом потеряется молча: человек увидит подтверждение на сайте, а сообщение не придёт. Вариант на Cloudflare лежит в `lead-proxy/cloudflare-worker.js` на случай зарубежной аудитории.

В Telegram уходит готовое сообщение с подписями полей (форма, имя, телефон, ответы квиза, посчитанная вилка цены, страница).
